# 모듈 규격 (ProcLevelGen)

미리 만든 방 모듈을 문 소켓으로 이어 붙이는 생성기의 규격입니다. 이 규칙만 지키면 어떤 방이든 카탈로그에 넣어 섞을 수 있습니다.

## 1. 피벗

| 항목 | 규칙 |
|---|---|
| 위치 | **바닥 사각형(풋프린트)의 정중앙, 바닥 윗면 높이 (Z = 0)** |
| 회전 | 피벗을 축으로 90° 단위만 (0 / 90 / 180 / 270) |
| 층 | 위층 모듈의 피벗은 Z = 400의 배수 |

중앙에 두는 이유:
- 90° 돌려도 피벗이 제자리에 있고 가로·세로 크기만 바뀝니다. 그래서 소켓 위치 계산과 겹침 검사가 단순합니다.
- 모서리 피벗은 돌릴 때마다 방이 피벗 바깥으로 밀려나서 보정 계산이 필요합니다.

바닥 윗면에 두는 이유:
- 캐릭터, 가구, 스폰 포인트를 모두 Z = 0 기준으로 놓을 수 있습니다.
- 층을 쌓을 때도 층 높이(400)만 더하면 됩니다.

언리얼에서 모듈을 Level Instance나 블루프린트로 만들 때도 같은 점을 원점으로 둡니다.

## 2. 그리드와 크기

| 항목 | 값 |
|---|---|
| 그리드 | 50cm |
| 풋프린트 크기 | **100cm의 배수.** 중앙 피벗이 50cm 그리드 점 위에 오게 하려는 것 |
| 소켓 위치 (Offset) | 50cm 배수 |
| 범위 | 생성기에서 5,000cm 안 (`MaxHalfExtent`). 내비 범위 볼륨 하나로 덮기 위함 |

## 3. 벽과 바닥

| 항목 | 값 |
|---|---|
| 벽 높이 | 400cm (한 층) |
| 벽 두께 | 20cm. **모듈마다 풋프린트 안쪽으로 절반(10cm)만 짓습니다.** 두 모듈이 맞닿으면 합쳐서 20cm |
| 바닥 | 두께 20cm, 윗면 Z = 0 |
| 외벽 | 이웃이 없는 면은 10cm. 그레이박스에서는 그대로 둡니다 |

## 4. 문 소켓

| 항목 | 규칙 |
|---|---|
| 위치 | 풋프린트 가장자리 위의 한 점. 방향은 바깥쪽 |
| 변 | 모듈 기준 `PosX` / `PosY` / `NegX` / `NegY` |
| Offset | 변 가운데에서 변을 따라 cm (X쪽 변은 +Y 방향, Y쪽 변은 +X 방향이 +) |
| 폭 | 150 (작은 문) / 300 (이중문). 높이 250 |
| 모서리 여유 | 문 끝에서 모서리까지 최소 50cm (그리드 한 칸) |
| 연결 | 위치가 같고, 서로 마주 보고, 폭이 같을 때만 연결 |
| 안 쓴 소켓 | 막힌 벽 |

## 5. 스폰 포인트와 소품

| 항목 | 규칙 |
|---|---|
| 스폰 포인트 | 모듈 기준 위치(바닥 윗면 Z = 0)와 방향(Yaw), 태그. 무엇을 놓을지는 게임이 태그로 정함 |
| 샘플 태그 | `Item` 바닥에 놓는 물건 · `HideSmall` / `HideLarge` 벽에 붙여 방 안을 보는 1인 / 2인 숨는 곳 · `Guard` 몬스터 대기 위치 |
| 소품 상자 | 모듈 기준 상자(중심, 크기). 그레이박스와 같이 모든 컴퓨터에서 지으므로 복제가 필요 없음 (책상, 선반) |
| 검사 | 스폰 포인트와 소품이 풋프린트 밖으로 나가면 경고 |

게임은 생성이 끝난 뒤 `GetSpawnSlots(태그)`로 월드 위치를 받습니다. 무작위 선택은 시드에서 만든 `MakeContentStream()`으로 하고, 배치는 서버에서 합니다.

## 6. 생성 순서

1. 시작 방(Start)을 원점에 둡니다.
2. 허브(Hub)를 시작 방의 문에 붙입니다.
3. 열린 문 중 하나를 무작위로 고르고, 통로나 일반 방을 붙입니다. 방 개수(`RoomCount`, 기본 4)가 찰 때까지 반복합니다.
   - 붙일 때는 겹침 검사를 합니다. 풋프린트끼리 변은 공유해도 되지만 면적은 겹치면 안 됩니다.
   - 새 방의 다른 문이 이미 열린 문과 딱 맞으면 둘을 이어서 고리를 만듭니다.
   - 아무것도 안 맞는 문은 벽으로 남깁니다.
4. 끝 방(End)을 가장 깊은(시작에서 문을 가장 많이 거친) 열린 문에 붙입니다.
5. 막다른 통로를 지웁니다. 연결이 하나뿐인 통로는 없앱니다.
6. 일반 방에 테마를 섞어서 나눠 줍니다. 앞의 방들끼리는 겹치지 않게 합니다.

실패하면 같은 시드에서 파생한 시드로 최대 16번 다시 시도합니다. 같은 시드는 모든 컴퓨터에서 같은 맵을 만들기 때문에, 멀티플레이에서는 서버가 시드만 보냅니다.

## 7. 샘플 키트 (고정 방 3 + 일반 방 틀 2 + 통로 3)

| 모듈 | 역할 | 크기 (X × Y) | 문 |
|---|---|---|---|
| Start (현관 홀) | Start | 1000 × 1000 | +X 이중문 |
| Hub (회전목마 홀) | Hub | 1600 × 1600 | ±X 이중문, ±Y 작은 문 |
| End (다락 침실) | End | 800 × 800 | −X 작은 문 |
| RoomSmall | Room | 800 × 800 | −X, +X, +Y 작은 문 |
| RoomLarge | Room | 1200 × 1000 | −X 이중문, +X 작은 문, +Y(Offset +300)·−Y(Offset −300) 작은 문 |
| CorridorStraight | Corridor | 800 × 300 | 양 끝 작은 문 (가중치 2) |
| CorridorCorner | Corridor | 300 × 300 | −X, +Y 작은 문 |
| CorridorT | Corridor | 300 × 300 | −X, +X, +Y 작은 문 |

시드 2,000개로 검사한 결과(파이썬 이식본)는 이렇습니다.
- 모두 첫 시도에 성공했습니다.
- 겹침, 한쪽만 이어진 문, 끊긴 방, 막다른 통로는 없었습니다.
- 한 맵의 모듈 수는 7~19개, 평균 8.5개입니다.

## 8. 아직 안 하는 것

- 실제 방 내용물 (Level Instance), 재질 테마 적용: 테마는 지금은 색만 바꿉니다
- 층 이동 (다락 2층 계단)
- 생성 결과 자동 검사 (커맨드릿): STEP 8
