# Tripo 협업 콘텐츠 구성안 (초안)

> 노트폴리오 × Tripo AI 네이버 블로그 협업 제안 회신용.
> 회신 항목 3번 "제작 가능한 콘텐츠 형식과 예상 분량"에 대한 초안.
> Tripo 측 콘텐츠 가이드를 받기 전 제안이며, 가이드에 맞춰 구성과 분량을 조정한다.

## 1. 원칙

- Tripo 편은 **Tripo 기능이 주인공**인 글로 쓴다.
- Tripo에서 만들지 않은 셰이더, 게임 시스템, 자동화 작업은 **별도 편**으로 분리한다.
- 게임(꿈 수거반) 소개는 도입부 한두 줄로만 쓴다.
- 각 단계는 "어떤 Tripo 기능을, 어떤 설정으로, 왜 썼는지"가 보이게 쓴다. (4장 기능 가이드 참고)
- 기능 이름과 메뉴 위치는 2026년 10월 Tripo 블로그 기준이다. 제공받는 이용 환경에서 실제 화면을 보고 확정한다.

## 3. Tripo 편 글 구성

### 제목안
1. 혼자 만드는 인디 게임, Tripo로 광대 인형 캐릭터 4종 만들기
2. 1인 개발자의 Tripo 에셋 제작기: 컨셉 이미지부터 언리얼 임포트까지

### 파이프라인 한 줄 요약 (글에 넣을 문구)
```
컨셉 이미지 → 레퍼런스 다듬기 → Smart Mesh(P2.0) → Edit Mesh → Smart UV → 텍스처 + PBR → Auto Rig → 애니메이션 미리보기 → FBX 내보내기 → Unreal
```

| 글 섹션 | 내용 | 사용 Tripo 기능 (4장) | 이미지·GIF |
|---|---|---|---|
| 0. 도입 | 협찬 표기, 게임 한두 줄 소개, 완성 모델 4종 대표 이미지 | — | 이미지 1~2 |
| 1. 제작 개요 표 | 대상, 인원 1명, 사용 기능, 소요 시간, 크레딧 | — | 0 |
| A. 컨셉과 레퍼런스 | 공통 스타일 문구, 컨셉 생성, A포즈·단색 배경으로 다듬기 | 4.1 | 이미지 3~4 |
| B. 베이스 메시 | P2.0 폴리곤 수 비교, 멀티뷰, Edit Mesh로 부분 수정 | 4.2 | 이미지 4~5 |
| C. UV와 텍스처 | Smart UV 활용률, Remove Lighting 켬/끔 비교, Texture Edit, PBR | 4.3 | 이미지 4~5 |
| D. 리깅과 애니메이션 | UE5 Mannequin 프리셋 Auto Rig, 애니메이션 미리보기, 4종 공유 | 4.4 | 이미지 2~3, GIF 1~2 |
| E. 내보내기와 언리얼 임포트 | FBX 옵션, Unreal Bridge, 임포트 후 확인 (셰이더 미적용 상태) | 4.5 | 이미지 2~3 |
| (F. 골동품 프롭 맛보기) | 대표 2~3개, P2.0/H3.1 선택, 유리 재질 결과 | 4.6 | 이미지 2~3 |
| G. 정리 | 소요 시간·크레딧 실측, 직접 손본 부분, 다음 편 예고 | — | 0~1 |

F는 분량에 따라 다음 편으로 미룰 수 있다.

### 구성 변형안: Agentic Canvas 활용

Agentic Canvas는 2026-10-29에 공개된 신기능(베타)이라 Tripo 쪽에서 소개를 원할 가능성이 높다. 캐릭터 4종을 **같은 워크플로로 반복 생성**해야 하는 꿈 수거반 상황과 잘 맞는다.

| 글 섹션 | 내용 |
|---|---|
| B~D 앞부분 | 첫 캐릭터(곰 광대)는 3D Workspace에서 단계별로 만들며 기능을 하나씩 설명 (4.1~4.5) |
| B~D 뒷부분 | 같은 과정을 Agentic Canvas 워크플로로 저장하고, 입력 이미지만 바꿔 나머지 3종 생성 (4.7) |
| 비교 | 3D Workspace와 Agentic Canvas의 작업 방식 비교 ([Canvas 캐릭터] 글의 비교표 형식) |

- 이용 대상이 Max·Team 우선이라 협업 이용 환경에서 쓸 수 있는지 먼저 확인해야 한다.
- Canvas를 쓰면 글이 길어지므로, 쓸 수 있다면 "Canvas 편"을 따로 두는 것도 방법이다.

## 4. 단계별 Tripo 기능 가이드

각 항목은 **기능 → 위치·설정 → 꿈 수거반 적용 → 확인 포인트 → 글에 넣을 캡처** 순서.

### 4.1 A단계: 컨셉과 레퍼런스

**시작 위치**
- studio.tripo3d.ai → 3D Workspace. 드롭다운에 `High Detail Model`, `Smart Topology Mesh`, `Generate Image` 세 가지 시작 옵션이 있다. 컨셉부터 만들 때는 `Generate Image`. [P2.0 캐릭터]

**Generate Image (컨셉 생성)**
- 프롬프트 직접 작성, 템플릿, 또는 둘을 함께 사용.
- 프롬프트 작성 순서: **대상 → 재질과 핵심 디테일 → 스타일**. 포즈는 생성 전에 정하고, 결과를 다듬을 때는 한 번에 한 가지만 바꾼다. [P2.0 캐릭터]
- 이 단계는 영감용. 여러 장을 뽑고 형태가 명확하게 읽히는 것을 고른다.

**Edit Image (레퍼런스 다듬기)**
- 생성한 이미지 클릭 → `Edit Image` → 이미지 편집 모델 선택(블로그 권장: Nano Banana Pro, GPT Image 2.5) → 바꿀 내용을 프롬프트로 입력. [P2.0 캐릭터]
- 좋은 3D 레퍼런스 조건: 순백색이나 단색 회색 배경 / 그림자가 베이크되지 않는 균일한 조명 / 대상이 화면의 70~90% / T포즈 또는 A포즈.
- 블로그 강조점: **레퍼런스 품질이 결과 품질을 결정한다.** 가장 영향이 큰 단계.

**템플릿**
| 템플릿 | 용도 | 출처 |
|---|---|---|
| T Pose | 표준 A/T 포즈와 깔끔한 배경을 한 번에 생성 | [P2.0 캐릭터] |
| Head Extraction | 머리만 별도 에셋으로 추출 (머리에 폴리곤·텍스처 예산을 더 줄 때) | [P2.0 캐릭터], [스튜디오 사례] |
| Character Extraction | 컨셉을 파트별로 분리 (More Templates 안). 후보 4개 반환 | [스튜디오 사례] |
| 3D Enhance | 레퍼런스를 PBR 느낌으로 보정 | [스튜디오 사례] |

**직접 그린 스케치에서 시작하는 방법** [스케치→캐릭터]
- 스케치 → 이미지 생성 도구(GPT Image 2.0, Nano Banana 등)로 **캐릭터 디자인 시트** 제작 → 디자인 시트를 확정 레퍼런스로 삼아 **T포즈 이미지** 생성.
- T포즈 생성 프롬프트에 "의상을 새로 디자인하거나 단순화하지 말 것"을 명시해 원래 디자인을 유지.
- 여러 변형을 생성해 원래 컨셉과 가장 잘 맞는 것을 고른다.
- 이미지 편집은 1회 10크레딧, 4K 업스케일은 이미지당 10크레딧. [문서: 요금]

**꿈 수거반 적용**
- `Tripo_Asset_List.md`의 캐릭터 공통 문구(2.5등신, 러프 칼라, 고깔모자, 바느질 자국, A-pose) + 캐릭터별 문구로 4종 컨셉 생성.
- 상업 게임이므로 직접 그린 스케치에서 출발하는 [스케치→캐릭터] 방식이 저작권 면에서 가장 안전하고, 글의 이야깃거리로도 좋다.
- 4종 모두 **같은 체형·같은 A포즈**가 되도록 T Pose 템플릿이나 Edit Image로 맞춘다. (D단계 애니메이션 공유의 전제)
- 머리 분리 생성(Head Extraction)은 디테일이 좋아지지만 조립과 리그 재연결이 필요하다. [P2.0 캐릭터] 14단계에서도 별도 머리는 몸통 리그와 자동으로 맞지 않는다고 설명한다. 2.5등신 인형은 **전신 한 번에 생성을 기본**으로 하고, 머리 분리는 비교 실험 정도로만 다룬다.

**확인 포인트**
- 4종의 실루엣, 비율, 포즈가 같은가
- 배경이 단색이고 그림자가 몸에 베이크되지 않았나

**글에 넣을 캡처**
- 컨셉 후보 여러 장 → 선택한 1장
- Edit Image 전/후 (배경, 포즈 정리)
- 4종 레퍼런스 나란히

### 4.2 B단계: 베이스 메시 (Smart Mesh P2.0)

**시작**
- 레퍼런스 이미지에 마우스 올림 → `Generate 3D` → `Smart Topology Mesh`. 또는 Model 패널에서 Smart Mesh 선택. [P2.0 캐릭터]

**Generate Multi-view**
- 최대 4각도의 다중 시점 이미지 생성. 측면과 뒷모습을 제어할 수 있다. 정면으로 설명하기 어려운 실루엣이 있을 때 중요. [P2.0 캐릭터]
- 꿈 수거반: 고깔모자 방울, 러프 칼라 뒷면, 토끼 귀처럼 뒤쪽 형태가 중요한 부분에 사용.

**Topology 설정**
- `General Settings → Topology`에서 토폴로지 유형(Quad / Triangle)과 폴리곤 수 설정. P2.0 선택 확인. [P2.0 캐릭터]
- P2.0 폴리곤 범위: 500~50K, 생성당 변형 4개, 다중 뷰 입력 지원. [GPT 씬]
- 구독자는 **폴리곤 수를 달리해 최대 4개를 한 번에 생성**할 수 있고, 개수와 관계없이 크레딧은 같다. 첫 시도에서 낮은 값~높은 값을 고루 배정해 적정 예산을 찾는다. [P2.0 캐릭터]
- 블로그 예시: 머리를 5K~9K로 4번 생성 → 7K가 최적. [스튜디오 사례]는 머리 3K로 전체 30K 미만.
- 생성은 1분 이내, 뷰포트 하단 와이어프레임 토글로 엣지 흐름 확인. 결과를 못 쓰면 무료 재시도 가능. [스튜디오 사례]

**P2.0 사양과 기본값** [문서: P 시리즈]
| 설정 | 옵션 | 기본값 | 메모 |
|---|---|---|---|
| 모델 버전 | P2.0 / P1.0 | P2.0 | P2.0: Quad+Triangle, 10~40초. P1.0: Triangle만, 최대 20K, 약 2초 |
| 토폴로지 | Quad / Triangle | Quad | Quad = 리깅·편집용, Triangle = 정적 소품용 |
| 폴리곤 수 | Triangle 500~50K / Quad 500~25K | 5,000 | 적당히 시작해서 실루엣이 부족할 때만 올린다 |
| 생성 개수 | 1 / 2 / 4 | — | 변형마다 폴리곤 수를 따로 설정 |
| 입력 | 단일 이미지 / 다중 뷰 / 텍스트 / 일괄 | 단일 이미지 | 복잡한 형태는 다중 뷰(최소 정면+측면, 최선은 4뷰) |

- 대칭은 자동 감지(별도 옵션 없음). 대칭 대상이 비대칭으로 나오면 레퍼런스가 기울어지지 않았는지 확인.
- 검사 도구: **와이어프레임 보기**(엣지 흐름), **홀로그램 셰이더**(겉면을 투과해 내부 구조, 겹친 메시 확인). 블로그와 제품 문서 모두 스무스·솔리드 뷰 전환도 권장. [스케치→캐릭터]
- Quad를 유지하려면 **FBX로 내보내기**. OBJ·GLB는 삼각형으로 바뀔 수 있다.
- 다중 뷰 이미지끼리 조명·배경·크기가 다르면 결과가 어긋난다.
- 부위별 참조 이미지 선택 [UE5 걷기]: 복잡한 신발·머리카락은 3면도, 단순한 의상은 1면도로도 충분.

**Edit Mesh (부분 재생성)**
- 하단 메뉴 → `Edit Mesh` → 노란 상자가 나타남 → 핸들로 고칠 영역을 감싸기 → `Retry Selection`. [P2.0 캐릭터]
- 나머지는 그대로 두고 그 부분만 다시 생성. 전체 재생성으로 잘 나온 부분까지 잃는 것을 막는다.

**꿈 수거반 적용**
- 목표: 캐릭터 1만 tri 이하. 첫 생성은 예를 들어 4K / 6K / 8K / 10K로 4개 동시 생성해 비교.
- 귀, 모자 방울, 손가락처럼 작은 돌출부에 구멍이나 뭉개짐이 생기면 Edit Mesh로 수정.

**확인 포인트**
- Topology가 Quad인지, 면 수와 정점 수 (Claude 연동 글처럼 수치를 글에 기록)
- 와이어프레임에서 얼굴·관절 부위 엣지 흐름

**글에 넣을 캡처**
- Topology 설정 패널
- 폴리곤 수별 4개 결과 비교 (와이어프레임 포함)
- Edit Mesh 노란 상자 선택 화면, 수정 전/후

### 4.3 C단계: UV와 텍스처

**Smart UV**
- 왼쪽 패널 `Smart UV` → `Unwrap UV`. [P2.0 캐릭터]
- 구조에 맞춰 심을 배치하고 큰 UV 아일랜드로 촘촘하게 패킹.
- 추가로 3번 무료 재생성 가능. 결과마다 **Utilization(활용률)** 수치 표시. 메시를 클릭하면 UV 레이아웃에서 위치 확인. 마음에 들면 `Save`, 아니면 `Retry`.
- 주의: **새 Smart UV를 저장하면 현재 텍스처가 제거될 수 있다.** 텍스처 생성 전에 UV를 먼저 끝낸다. [Claude 연동]
- 활용률이 유일한 목표는 아니다. 얼굴처럼 중요한 부위에 충분한 공간이 있는지 같이 본다. [Claude 연동] (예시 수치 79.9%)

**Texture 생성**
- 왼쪽 패널에서 확장 옵션 사용. 모델 생성에 쓴 레퍼런스 이미지가 기본으로 들어가 있어야 함. [P2.0 캐릭터]
- `Remove Lighting`: 레퍼런스의 베이크된 조명을 줄여 엔진 조명에 반응하는 텍스처를 만든다. 켜면 일부 디테일이 흐려질 수 있어 블로그는 켬/끔 두 버전을 모두 보관했다. 정답 설정은 없고 아트 스타일에 맞춘다.
- 해상도: 블로그는 8K를 원본으로 뽑고 최종은 4K나 2K로 낮춤. 생성은 몇 분 소요. [스튜디오 사례]
- 제품 문서 기준 [문서: 텍스처]
  | 설정 | 옵션 | 기본값 | 권장 |
  |---|---|---|---|
  | 텍스처 품질 | 2K / 4K / 8K | 2K | 프로토타입 2K, 실제 제작 4K, 클로즈업 핵심 에셋만 8K |
  | 조명 제거 | 켜기 / 끄기 | 끄기 | 자체 조명이 있는 엔진 장면에 넣을 거면 켜기 |
  | 입력 | 텍스트 / 참조 이미지 | 텍스트 | 특정 외관 재현은 참조 이미지 |
- 시작 방식 세 가지: HD 모델 + 텍스처 동시 생성 / Smart Mesh 생성 후 텍스처 적용 / 왼쪽 텍스처 탭의 **독립형 텍스처**(업로드한 모델에도 적용 가능).
- 같은 모델에 텍스처를 여러 번 다시 입혀도 메시는 변하지 않는다. 크레딧은 해상도 등급에 따라 다르고 생성 전에 표시된다.
- 프롬프트는 구체적으로: "나무 텍스처"보다 "나뭇결이 선명한 오래된 참나무".

**Texture Edit**
- 텍스처 옵션 아래 `Edit` → 다시 칠할 내용 설명 → `Generate Preview` → 투영 오버레이로 표시 → `Save`. [P2.0 캐릭터]
- 주의: **현재 보는 각도에만 적용**된다. 앞에서 칠하면 뒤는 그대로. 부분 보수용 도구.
- 텍스트 프롬프트 외에 **브러시로 직접 칠하는 편집**도 있다. [스케치→캐릭터] 튜토리얼 센터에서는 Magic Brush라는 이름으로 소개된다. [튜토리얼 센터]
- 텍스처 업스케일로 더 높은 해상도를 얻을 수 있다. [스케치→캐릭터]

**PBR**
- 왼쪽 패널 `PBR` → 베이스 컬러 하나를 노멀, 러프니스, 메탈니스가 포함된 텍스처 세트로 변환. [P2.0 캐릭터]

**꿈 수거반 적용**
- 인형 천 질감, 바느질 이음새가 텍스처에 잘 나오는지가 핵심.
- Remove Lighting 켬/끔 비교는 Tripo 화면과 언리얼 기본 조명 화면으로만 보여준다. (셰이더 적용 비교는 별도 편)
- 단추, 방울처럼 금속 느낌 부분은 PBR 메탈니스 결과 확인.

**확인 포인트**
- UV를 텍스처보다 먼저 저장했나
- 좌우, 가려진 부위(겨드랑이, 칼라 안쪽)에 색 차이가 없나

**글에 넣을 캡처**
- Smart UV 결과와 Utilization 수치
- Remove Lighting 켬/끔 비교
- Texture Edit 전/후
- PBR 맵 세트

### 4.4 D단계: 리깅과 애니메이션

**Auto Rig**
- 왼쪽 패널 `Rig` → 유형 선택(`Humanoid` / 동물 등은 `Other`) → Skeleton Preset 선택 → `Auto Rig`. [P2.0 캐릭터]
- 프리셋: `UE5 Mannequin`, ActorCore, Mixamo, VRM 1.0 Humanoid, Unity Humanoid Compatible 등.
- UE5 Mannequin 프리셋은 기본 UE5 스켈레톤과 호환되어 리타기팅 필요를 줄인다. [Claude 연동]
- 손가락 수준까지 리깅된다. Tripo에서 만들지 않은 업로드 모델에도 사용 가능.
- 제품 문서 기준 [문서: 리깅]
  - 지원 유형 7종: 인간형(두 발) + `기타`에 속하는 네발, 여섯 발, 여덟 발, 조류, 뱀, 어류. 네발 캐릭터가 자동 감지되지 않으면 수동 선택.
  - 리깅 20크레딧, 애니메이션 20크레딧.
  - Studio 안에서 스켈레톤·웨이트를 직접 고칠 수는 없다. 수정은 FBX로 내보내서 Blender·Maya에서.
  - 어깨, 엉덩이, 손가락이 자주 문제가 되는 부위. 어깨 변형은 자동 리깅에서 흔한 문제.
  - 애니메이션이 떨리면 다른 클립을 시도. 클립마다 맞는 신체 비율이 다르다.
  - 머리카락은 정적 메시로 취급된다(시뮬레이션 불가).
  - 리깅된 FBX는 Mixamo와 호환.

**Animate (애니메이션 미리보기)**
- 왼쪽 패널 `Animate`. [P2.0 캐릭터]
  - `Animation Preset Library`: 내장 애니메이션으로 테스트
  - `Text-to-Motion`: 텍스트로 동작 생성
  - `Multi-Stage Motion`: 걷기 → 점프처럼 여러 동작을 하나로 블렌딩
- 길이는 최대 10초.

**꿈 수거반 적용**
- 4종 모두 Humanoid + UE5 Mannequin으로 리깅 → 같은 스켈레톤이라 언리얼에서 애니메이션 한 세트를 공유.
- Text-to-Motion으로 게임 동작 시연: "무거운 상자를 두 팔로 들고 뒤뚱뒤뚱 걷기", "넘어져서 주저앉기" 같은 프롬프트.
- 러프 칼라와 고깔모자는 머리카락처럼 정적으로 따라 움직이므로, 클리핑이 없는지 중점 확인.
- 2.5등신은 일반 인간형과 비율이 달라 애니메이션 클립마다 결과가 다를 수 있다 → 여러 클립 비교가 글 소재.
- (몬스터 편으로 미룰 경우) 종 달린 말은 `기타 → 네발`로 공식 지원 범위 안이다. 몬스터 편의 핵심 소재.

**확인 포인트**
- 어깨, 팔꿈치, 손목, 엉덩이, 무릎, 발목 위치와 좌우 대칭 [Claude 연동]
- 어깨가 무너지거나 팔이 몸을 뚫거나 무릎이 반대로 꺾이는지, 러프 칼라·모자 같은 부착물 클리핑 [Claude 연동]
- 짧은 팔다리, 큰 머리(2.5등신) 비율에서 자동 리깅이 잘 맞는지 — 글의 솔직한 관찰 포인트

**글에 넣을 캡처**
- Rig 설정 화면 (Humanoid, UE5 Mannequin)
- 스켈레톤 오버레이
- 애니메이션 GIF 1~2개 (프리셋 1, Text-to-Motion 1)

### 4.5 E단계: 내보내기와 언리얼 임포트

**Export**
- 형식 `FBX`, `Export Skeleton` 켜기, `Number of Animations`에서 포함할 애니메이션 선택, 필요하면 `Animation stay in Place` 켜기(제자리 애니메이션, 블렌딩에 유리). [Claude 연동]
- 내보내기 전 체크리스트: Topology Quad / UV 저장 / 텍스처 정상 / UE5 Mannequin 리깅 완료 / 애니메이션에 관절 오류 없음 / FBX에 스켈레톤과 애니메이션 포함. [Claude 연동]

**DCC Bridge / Unreal Bridge**
- 플러그인을 설치하면 내보내기·가져오기 없이 에셋을 바로 전송. 설치 가이드는 문서 아이콘에서 확인. [P2.0 캐릭터]
- 주의: 자동 동기화 시 **Tripo 웹페이지와 받는 프로그램(언리얼)이 동시에 열려 있어야** 한다. 닫혀 있으면 전송 실패.
- Unreal Engine Bridge는 **UE 5.4 이상**. Blender Bridge는 4.1 이상, Unity·Godot·Cocos·ComfyUI도 지원. [게임 개발 소개]

**언리얼 임포트 (Tripo 결과 확인 범위까지만)**
- FBX 임포트 시 Skeletal Mesh로 인식되는지 확인. 첫 캐릭터는 새 Skeleton 생성, 이후 캐릭터와 애니메이션은 그 Skeleton 선택. 애니메이션만 추가할 때 `Import Only Animations`. [Claude 연동]
- 크기·방향, 머티리얼, 스켈레톤 계층, 애니메이션 재생 확인.
- **엔진에서 머티리얼 다시 확인**: [스케치→캐릭터] 예시에서는 얼굴에 의도하지 않은 금속성 반사가 생겨 메탈릭을 꺼서 해결했다. 인형 천 재질에 금속성이 잘못 들어가지 않았는지 확인.
- 머리 안의 눈·이빨처럼 숨은 부품은 머티리얼 할당을 놓치기 쉽다. [UE5 걷기]

**꿈 수거반 적용**
- 첫 캐릭터(예: 곰 광대)를 임포트할 때 만든 Skeleton을 나머지 3종이 공유하는 장면을 보여준다.
- 화면은 **셰이더 미적용 기본 상태**로. 그레이박스 큐브와 교체 비교 1컷까지는 Tripo 에셋 효과를 보여주는 장면이라 포함.

**글에 넣을 캡처**
- Export 옵션 화면
- Unreal Bridge 전송 또는 FBX 임포트 창
- 언리얼 뷰포트의 캐릭터 4종

### 4.6 (선택) F단계: 골동품 프롭

**모델 선택 기준** [GPT 씬]
| 모델 | 특징 | 꿈 수거반 용도 |
|---|---|---|
| HD Model (H3.1) | 최대 약 200만 면 하이폴리, 8K 텍스처·PBR, 다중 뷰 입력. Nanite 정적 에셋에 적합 | 회전목마, 괘종시계 같은 랜드마크 (고정 배치) |
| Smart Mesh (P2.0) | 깔끔한 로폴리, Quad/Triangle, 500~50K 면, 생성당 4개, 부분 편집 | 들고 옮기는 골동품 (물리 대상, 3천 tri 이하) |

**작업 방법**
- 대표 에셋 하나로 설정을 먼저 검증한 뒤 나머지를 생성. 실패하거나 배경이 섞인 에셋은 **전체를 다시 하지 말고 개별 재시도**. [GPT 씬]
- 모든 에셋에 "배경 없음, 받침 없음" 규칙 통일 (`Tripo_Asset_List.md` 공통 스타일 문구와 같음).
- **이미지 일괄 3D 생성**: 3D 작업 공간 → HD 모델 또는 스마트 토폴로지 메시 → 입력 패널의 `일괄 처리` → 이미지 여러 장 업로드 → 같은 설정으로 대기열 처리 → 개별 미리보기 또는 일괄 다운로드. 한 번에 최대 10개(Starter·Professional), 30개(Max·Team). [문서: 일괄], [문서: 요금]
- 들고 옮기는 정적 소품은 리깅이 필요 없으므로 **Triangle 토폴로지**도 선택지. 같은 폴리곤 수에서 디테일이 더 많다. [문서: P 시리즈]

**꿈 수거반 적용**
- 크리스탈 쿠페 잔, 향수병처럼 **투명 유리** 재질이 어떻게 나오는지 → 솔직한 한계와 보완 소재.
- 회전목마 말(L 등급)처럼 큰 물건은 P2.0와 H3.1 결과를 비교해볼 수 있음.

### 4.7 (변형안) Agentic Canvas

**무엇인가** [Canvas 소개], [문서: Canvas]
- 생성부터 내보내기까지의 3D 워크플로를 AI Agent가 계획하고, 노드 기반 캔버스에서 실행하는 기능. 2026-10-29 공개, 베타.
- 이용 대상: Max·Team 우선, 다른 계정에 순차 제공. 무료 사용자는 24시간 체험. Studio 왼쪽 위 메뉴에 Agentic Canvas가 보이면 사용 가능.
- 한 번의 생성·편집만 필요하면 3D Workspace가 더 빠르다. 여러 단계를 잇거나 반복 작업이 있을 때 Canvas가 유리.

**주요 노드**
| 노드 | 기능 |
|---|---|
| Upload | 이미지나 모델을 캔버스에 추가 |
| Generate Image | 참조 이미지 생성·변경 |
| Element Extraction | 이미지에서 요소(예: 머리)만 별도 이미지로 추출 |
| Multi-view | 앞·뒤·왼쪽·오른쪽 뷰 생성 |
| Cutout | 배경 제거 |
| HD Model / Smart Mesh | 3D 모델 생성 |
| Segmentation | 모델을 부위별로 분할 |
| Retopology | 목표 폴리곤 수로 재구성 |
| Smart UV / Texture Generation / PBR | UV, 텍스처, PBR 맵 |
| Rigging | 스켈레톤 추가 |
| AI 3D Lab | 대화로 에셋 검사·복구·조립·편집 |

- 리깅된 모델은 Retopology나 Segmentation으로 넘길 수 없다. PBR은 베이스 컬러 텍스처가 있어야 한다.

**작업 방식** [Canvas 캐릭터]
- `Create New Canvas` → 참조 이미지 업로드 → Agent에게 목표만 말하기 (예: "게임에서 사용할 수 있는 캐릭터를 만들어 줘").
- 모드: **Control**(주요 단계마다 멈춰서 검토) / **Auto**(확인된 계획대로 진행). 처음에는 Control 권장, 새 프로젝트는 Control로 시작.
- Agent가 실행 전에 단계별 계획을 보여준다. **계획 확인에는 크레딧이 들지 않고**, 승인 후 생성부터 차감.
- 고칠 부분만 새 노드로 분기해서 수정. 기존 결과는 지워지지 않는다.
- 워크플로를 저장해 **입력만 바꿔 재사용**. AI 3D Lab은 대화 내용을 Task instructions로 저장해 `Reuse instruction`으로 새 입력에 다시 적용.

**꿈 수거반 적용**
- 곰 광대로 만든 워크플로(Smart Mesh → Smart UV → Texture → PBR → Rigging)를 저장 → 쥐·개구리·토끼 레퍼런스로 입력만 교체해 실행.
- "4종이 같은 설정으로 만들어졌다"는 점이 일관성 확보 이야기와 연결된다.
- 골동품 20종도 같은 방식으로 재사용 가능 (프롭용 워크플로 따로 저장).

**글에 넣을 캡처**
- Agent 계획 화면, Control 모드에서 멈춘 화면
- 완성된 노드 그래프 전체
- 입력만 바꿔 4종이 나란히 나온 결과
